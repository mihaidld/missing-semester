Fixed:
"${myarray[@]}" expands to all elements of the array [@]
and leads to each element of the array being treated as a separate shell-word
*.m3u is a globbing which expands to an arry containg all files that include
m3u in their name (e.g. M3U8 video format is a video file format for streaming,
a playlist text files with the URLs of video files)
grep -q or quiet mode suppresses normal output, we all need exit code for grep to evaluate 2nd expression after &&
grep -i ignores case so we search for any file that contains hq / HQ and later mp3

#!/bin/sh
for f in "${*.m3u[@]}"
do
  grep -qi "hq.*mp3" "$f" \
    && echo "Playlist $f contains a HQ file in mp3 format"
done

or simpler

#!/bin/sh

for f in *.m3u
do
grep -qi "hq.*mp3" "$f" \
   && echo "Playlist $f contains a HQ file in mp3 format"
done

5. Here are some sorting algorithm implementations (sorts.py). Use cProfile and line_profiler to compare the runtime of insertion sort and quicksort. What is the bottleneck of each algorithm? Use then memory_profiler to check the memory consumption, why is insertion sort better? Check now the inplace version of quicksort. Challenge: Use perf to look at the cycle counts and cache hits and misses of each algorithm.
 
python -m cProfile -s tottime sorts.py
quicksort has tottime 0.03, quicksort_inplace 0.023, insertionsort 0.015

LINE_PROFILE=1 python sorts.py #to run with line profiler
python -m line_profiler -rtmz profile_output.lprof #to view profiler results

quicksort spends most time on last line (return quicksort(left) + [pivot] + quicksort(right) 38008, then on computing length of the array using the builtin len function (if len(array) <= 1:) 20399
quicksort_inplace spends most on builtin range function with for iteration (for i in range (low, high):) 71834, then if array[i] <= pivot: 54923
insertionsort spends most time on while loop while j >==0 and v < array[j] 126664, then array[j+1] = array[j]
In total 0.11 seconds for quicksort, 0.35 for quicksort_inplace and 0.39 for insertionsort

After commenting line importing line_profiler:
python -m memory_profiler sorts.py
insertionsort uses same memory 20.207 MiB without any increments in memory usage, while quicksort needs increments in memory consumption since it needs to create new subarrays left and right, quicksort_inplace doesnt add increments in memory consumption since it makes like insertionsort swaps in place.

7. A common issue is that a port you want to listen on is already taken by another process. Let’s learn how to discover that process pid. 
First execute python -m http.server 4444 to start a minimal web server listening on port 4444. 
On a separate terminal run lsof | grep LISTEN to print all listening processes and ports. Find that process pid and terminate it by running kill <PID>.

lsof -PiTCP:4444
Find all open files with lsof with options -P (to avoid using port names like krb524 and use instead their port numbers, -i to select iPv4 and IPv6 files with protocol TCP and port number 4444 TCP:4444
COMMAND   PID        USER   FD   TYPE            DEVICE SIZE/OFF NODE NAME
Python  31252 mihaidoldur    4u  IPv6 0xc01e2e1a7be4976      0t0  TCP *:4444 (LISTEN)

Then kill that process with
kill 31252

8. Limiting a process’s resources can be another handy tool in your toolbox. Try running stress -c 3 and visualize the CPU consumption with htop. Now, execute taskset --cpu-list 0,2 stress -c 3 and visualize it. Is stress taking three CPUs? Why not? Read man taskset. Challenge: achieve the same using cgroups. Try limiting the memory consumption of stress -m.
stress -c 3 occupies 3 CPU's to 100% as per htop
taskset --cpu-list 0,2 stress -c 3 executes stress -c 3, but limits usage of only CPUs #0 and #2 as per --cpu-list option so uses only 2 CPUs as per man taskset. So in total only 5 CPUs are hogged.
