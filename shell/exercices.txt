2. Write bash functions marco and polo that do the following. 
Whenever you execute marco the current working directory should be saved in 
some manner, then when you execute polo, no matter what directory you are in, 
polo should cd you back to the directory where you executed marco. 
For ease of debugging you can write the code in a file marco.sh and 
(re)load the definitions to your shell by executing source marco.sh.

marco () {
    marcoPWD=$(pwd)
}
polo () {
    cd $marcoPWD             
} 

3. Say you have a command that fails rarely. In order to debug it you need to 
capture its output but it can be time consuming to get a failure run. 
Write a bash script that runs the following script until it fails and 
captures its standard output and error streams to files and prints everything 
at the end. Bonus points if you can also report how many runs it took for 
the script to fail.

 #!/usr/bin/env bash

 n=$(( RANDOM % 100 ))

 if [[ n -eq 42 ]]; then
    echo "Something went wrong"
    >&2 echo "The error was using magic numbers"
    exit 1
 fi

 echo "Everything went according to plan"

#!/bin/sh
a=1
times=1

# remove previous outputFails.txt
if [ -e outputFails.txt ]
then
    rm outputFails.txt
fi

while [ $a -ne 0 ]
do
   echo $times
   # execute script and append output files and overwrite error file
   # with values redirected from STDOUT and STDERR
   sh ./failsRarely.sh 2> errorFails.txt 1>> outputFails.txt
   
   # stop loop if error code not 0 
   if [[ $? -ne 0 ]]; then
      a=0
   else
      # increment value of times
      times=$((times+1))
   fi
done

cat outputFails.txt errorFails.txt
echo "Failed after $times times"

4. As we covered in the lecture find’s -exec can be very powerful for 
performing operations over the files we are searching for. 
However, what if we want to do something with all the files, like creating a 
zip file? As you have seen so far commands will take input from both arguments 
and STDIN. When piping commands, we are connecting STDOUT to STDIN, but s
ome commands like tar take inputs from arguments. 
To bridge this disconnect there’s the xargs command which will execute a 
command using STDIN as arguments. 
For example ls | xargs rm will delete the files in the current directory.

Your task is to write a command that recursively finds all HTML files in the 
folder and makes a zip with them. Note that your command should work even if 
the files have spaces (hint: check -d flag for xargs).

If you’re on macOS, note that the default BSD find is different from the one 
included in GNU coreutils. You can use -print0 on find and the -0 flag on 
xargs. As a macOS user, you should be aware that command-line utilities 
shipped with macOS may differ from the GNU counterparts; you can install the 
GNU versions if you like by using brew.

find . -name '*.html' -print0 | xargs -0 tar -cf target.tar

(find -print0 prints the pathname of the current file to standard output, followed by an ASCII NUL character (character code 0).
xargs -0 makes xargs to expect NUL (``\0'') characters as separators, instead of spaces and newlines.  
This is expected to be used in concert with the -print0 function in qfind(1).
tar -c Create a new archive containing the specified items
tar -f file reads the archive from or write the archive to the specified file)
